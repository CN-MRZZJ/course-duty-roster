# 数据与约束记录

用于混合材料解析、排班复核和多轮修改。结构可按任务简化，不要求创建数据库；JSON 或普通表格足够。

## 课程事件

建议字段：`person`、`weekday/date`、`course/activity`、`week_rule`、`period_start/end` 或 `start/end`、`source`、`certainty`。

- `source` 写文件名及 Excel 单元格、Word 表格位置或截图区域；聊天限制记录原话及消息顺序。
- 原始周次字符串与归一化的区间/单双周条件同时保留。
- 重复事件合并，但不同课程占用同一时段不能因去重丢失名称。
- 区分“教学周内某星期”与具体日期。特殊调课有可靠依据时按日期覆盖，不能自行根据自然周推断。
- 整周实践或集中实训单独建事件；不要只解析主课表。

## 班次

建议字段：`shift_id`、`date`、`label`、`start/end` 或 `periods`、`duration`、`required_staff`。

- `label` 与内部边界分离。隐藏钟点不会删除时间或改变求解权重。
- 有实际时长时以分钟保存数值；使用相对权重时记录基准及来源。
- 同一班次允许不同日期有不同人数或时长，但仅在原始要求确实存在这种差异时建立。

## 约束账本

| 字段 | 含义 |
|---|---|
| id | 稳定编号，如 C01 |
| subject / scope | 适用同学、日期、班次 |
| rule | 不可排、必须排、人数、上限或偏好 |
| strength | hard / soft |
| priority | 用户指定的软目标顺序 |
| source | 文件定位或聊天原话 |
| status | active / superseded / revoked |
| replaces | 被替代的规则编号（如有） |

例如：“小王尽量不值早班”为软偏好；“小王可以值早班，取消这项限制”应停用偏好，而不是新增一个必须上早班的规则。

“小贺周五全天不可排”应让周五所有班次不可用，而不是只移除当前占用的一个班次。“周三下午第一班只有小朱可排”需要更新整个班次候选集。

## 可用性

每条记录保存：`person`、`shift_id`、`status`（available / unavailable / unknown）、`reasons`、`sources`。

- 课程事实与用户覆盖分开保存。可以同时看到“原课表无课”与“用户确认当天不能值班”。
- 已知不允许的时段为 unavailable，即使另有未知课程也不改变这一结果。
- 材料不完整和未定节次课程保留 unknown 原因；求解器采用乐观还是保守处理需明确。
- 汇总表中的“不可排”不能全部归因于“有课”；标明用户限制、既有活动等不同来源。

## 每轮更新

只执行本轮变化：定位规则 → 更新状态 → 重建受影响候选集 → 求解或改标签 → 重新核验 → 更新展示和说明。

对影响结果的约束清单保留一份权威记录，避免分别维护脚本硬编码、表格备注和聊天摘要而出现不一致。材料、约束和结果分别保存，不从旧排班反推某人一定可用。
